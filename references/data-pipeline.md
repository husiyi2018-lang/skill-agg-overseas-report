# 取数管线

报告的数据来自 **[AppGrowing全球广告 AI 策略分析平台](https://appgrowing.ai)**，全部经 `aggclaw` 自然语言分析引擎取：

> 这是铁律 1 规定的**唯一合法署名写法**（`shell.html` 的 `side-foot` 已内置，`validate.py` 会校验）。
> 不要写成「appgrowing.ai」「AppGrowing Global 广告素材分析平台」等其它形式。

| 引擎 | 擅长 | 产物 |
|---|---|---|
| `aggclaw` 自然语言分析引擎 | 趋势解读、创意拆解、赛道对比、生命周期判断、维度聚合计数 | 大段分析文本 + 素材 ID 清单 |

**数字与分析同源**：量级、趋势、媒体/地区/素材类型分布等都由 aggclaw 在回答里给出，
素材实体再由会话素材接口拉清单。**aggclaw 报的数字就是唯一口径**，
多路（A 档）之间对不上时按下面的冲突规则处理，并在口径里说明。

## aggclaw 取数（分析 + 素材清单）

### 接入

```
POST https://ai-chat-global.youcloud.com/aichat/claw
Authorization: Bearer $YOUCLOUD_API_KEY
{"input": "<问题>", "chat_mode": 7, "language_code": "zh"}
```

- **`chat_mode`**：`7` = 游戏 / `8` = 非游戏(含短剧) / `9` = 灵感
- **超时必须 ≥ 600 秒**。单次 1–8 分钟，**提前中断返回空结果**
- 脚本：`scripts/aggclaw.py`

### 提问方式（关键）

**越轻越稳 —— 这是实测出来的，不是理论值。**

同一窗口、同一接口、同一台机器上的对照：

| 问法 | 子问题数 | 尝试 | 成功 |
|---|---|---|---|
| 重问法(量级+趋势+媒体+地区+时长+类型) | 6 | 4 | **0** |
| 轻问法(只问身份/量级/品类) | 3 | 1 | **1**(返回 7187 字) |
| 轻问法批量(6 路各 2–3 问,并发 3) | 2–3 | 6 | **6** |

**结论：把 6 个子问题拆成 2 个各 3 个的轻问题，成功率从"基本为零"变成"基本必成"。**
文档早先「别超过 7 个」的表述偏宽松 —— 实测 6 个就足以触发 600s 读超时，
而超时后 `claw.py` 会以**新会话重试一次**，等于再等 10 分钟：
**一个重问法烧掉 20 分钟且大概率一无所获；两个轻问法并行，10 分钟内双双到手。**

维度靠**多路轻问事后拼装**，不要指望单次调用给全。详见 `pitfalls.md` #35。

### 结构上取不到的提问（别问，问了也是白等）

| 问法 | 状态 | 替代 |
|---|---|---|
| 「XX 品类素材量前 8 的产品及各自素材数」 | **取不到** —— 接口为素材级数据，无产品归属字段，无法按产品聚合 | **点名指定产品**，每款一路，再自行汇总（实测 6/6 全成） |
| 「7 月 vs 8 月的环比」 | **算不出** —— 投放天数与曝光是**生命周期累计值，不随查询区间变化** | 改用「近 30 天新投放素材 + 首次发现时间」 |
| 「XX 产品的投放国家/地区分布」 | **取不到** —— 接口无国家/地区字段 | 改用**语言分布**作降级代理，并在口径里写明「语言≠国家」 |
| 「广告数」 | **取不到** —— 引擎不支持聚合 | 如实写「不可得」，不要拿抽样估算进正文 |

> 前三条都由引擎主动说明过理由（有的还明确拒绝回答而非硬凑数字）。
> **引擎拒绝时给出的理由本身是有价值的信息** —— 它划定了这套数据的边界，
> 直接写进报告的「数据口径与边界」章即可，比拿行业通用结论去填诚实得多。
> 详见 `pitfalls.md` #36。

实跑验证过的两段式：

**① 量级与分布**
```
请分析游戏 {产品名}({中文名},{开发商})在 {起} 至 {止} 的海外投放量级与分布:
1) 素材投放总量与广告数总量;
2) 逐周投放趋势(逐周给出素材数);
3) 主要投放地区 TOP10 及占比;
4) 主要投放媒体 TOP10 及占比;
5) Android/iOS 平台拆分占比;
6) 广告形式分布与素材类型占比;
7) 素材时长分布。
请给出具体数字,不要省略。
```

**② 创意策略**
```
请拆解游戏 {产品名} 在 {起} 至 {止} 的素材创意策略:
1) 主要素材方向有哪几类,各自的定位与占比;
2) 前3秒 Hook 的类型分布;
3) 玩法/功能是怎么表达展示的;
4) 是否使用 CTA 与变现话术,占比多少;
5) 素材中出现的核心画面元素(角色/建筑/UI/皮肤等);
6) 该产品近期是否在做联动活动,素材上如何体现。
请给出具体数字与代表性素材。
```

> 短剧类把「游戏」换成「短剧 App」、`chat_mode` 改 `8`，并把「玩法」换成「剧情/题材」。

### 交叉验证

**A 档必须做**。同一问题换**不同角度**问 ≥2 次（各自独立 session）：

| 路 | 问法角度 |
|---|---|
| R1 | 直接问总量与趋势 |
| R2 | 从「素材结构」切入，让它自己报总量 |
| R3 | 从「竞品对比」切入 |
| R4 | 从「头部素材」切入，反推总量 |

**置信度规则**：
- ≥2 路结论一致 → **高**，正文可断言
- 仅 1 路 → **机会点**，措辞降级为「数据显示…」
- 两路采样差异 >20% → **严禁取平均**。正文用主口径，并在「数据口径说明」注明分歧与原因

**已知失败模式**：
- **HTTP 200 但 body < 1KB 且含「系统繁忙」= 假成功**，勿入库
- **504 / 系统繁忙** → 把同一 input **当新会话重发**（独立样本，不破坏交叉验证）；最多重试 1 次，再失败标「未跑成」并由相邻路覆盖，口径注明
- **R1 趋势 / R2 结构 / R4 头部 = 最重的路**，最易 504
- **并发压到 ≤3** —— 8 路同时 POST 会网关 504，被掐在 ~600s

### 拿素材清单

```
GET https://ai-chat-global.youcloud.com/aichat/sessions/{session_id}/materials
```
- `session_id` 里的 `=` 要编码成 `%3D`（`~` 保留）
- 返回 `[{"id","detail_url","download_url","is_mentioned"}, …]`
- **字段就这些** —— 没有封面图、没有曝光/时长等指标，这些只能从 aggclaw 的分析文本里取
- 脚本：`scripts/claw.py materials`（`--scan raw/data` 把所有会话的清单汇总去重）
- 每个会话的元数据在同名 `.json` 里（`session_id` 等），分析原文在同名 `.md` 里 —— 分开落盘的理由见「目录约定」

### 脚本别起这些名字

`select.py` / `json.py` / `types.py` —— 与标准库同名，会让 `urllib.request` 在 Windows 上
`ImportError: cannot import name 'Request' from partially initialized module`（循环导入）。
**改叫 `pick.py` 之类。**

## 素材实体化（封面 + 视频）

### 封面

素材清单**没有封面图字段**，所以封面一律**从视频首帧抽**：`download_url` → ffmpeg 取 0.6 秒那一帧。
（0.6s 与 `frames.py` 的 Hook 帧同一时间点，画面口径一致。）

抓到帧后**必须压缩**（原图直嵌会让单文件到 20MB+）：
```python
from PIL import Image
im = Image.open(io.BytesIO(raw)).convert('RGB')
w = 360
im = im.resize((w, int(im.height * w / im.width)), Image.LANCZOS)
buf = io.BytesIO(); im.save(buf, 'JPEG', quality=72, optimize=True)
```
实测：2.44MB 原图 → 3.35MB base64 → 报告落在 2MB 出头。

- 脚本：`scripts/covers.py`（**依赖 ffmpeg**；没装会直接报错，不静默产出空结果）
- **`download_url` 常为完整长片**（几十 MB），不要整条内嵌

### 视频

**「先探体积、超了就不要」是不够的** —— 实测里超预算的恰恰是最有代表性的头部素材，
一砍就把证据链砍断了。**改成「一律重编码」**：

```
download(原片, 不限大小)
  → ffprobe 探宽高/时长
      · 无视频流(是 JPEG/PNG) → kind="image",原图直接当封面，结束
  → ffmpeg 重编码:
      -vf scale=270:-2
      -c:v libx264 -crf 32 -preset veryfast
      -pix_fmt yuv420p -profile:v baseline      # 老浏览器也能解
      -c:a aac -b:a 48k -ac 1                   # 单声道，音频几乎不占体积
      -movflags +faststart                      # 边下边播
  → 判体积: ≤ EMBED_MAX_MB(2.5) 且累计 ≤ TOTAL_MAX_MB(14.0) → base64 内嵌
             超出 → 封面兜底 + 口径注明
```

**标定实测**：`00c63c8` 原片 **15MB → 1.05MB（约 15:1）**。
所以**「原片多大」和「能不能内嵌」基本无关** —— 关键只在重编码参数。

> ⚠️ **15:1 是短片的数；长片差得多。** 实测 Magic Sort! 的素材多为 45–60 秒，
> 原片 1.7–4.4MB 重编码后仍剩 0.7MB 上下，只有约 **5:1**。
> 所以**素材普遍偏长时，别按 15:1 估预算** —— 会严重低估条数。

> ⚠️ **预算按「写进 HTML 的长度」算，不是按重编码后文件的字节数算。**
> 写进报告的是 base64，比原始字节大约 **1.37 倍**。旧版拿原始字节当闸门，
> 「14MB 预算」的产物实际带 ~19MB 载荷、报告胀到 23MB，而脚本自报的
> 「base64 合计约 13.8MB」看着完全合规 —— 要查载荷构成才发现。
> 现已改成按 `payload = len(data_uri)` 判，并在输出里同时打印「原文件 / 内嵌」两个数。
> 自己写组装脚本时，**取封面一律先查 `covers.json`**：反过来先查 `videos.json` 会把
> 整段视频 base64 当 poster 再存一遍，同一块载荷进文件两次。

> ⚠️ **`--force` 重跑必须先释放旧条目占的额度。** 旧版 `--force` 只把条目重新排进队列，
> 没从 `used` 里扣掉它们，于是起点就是「旧总量」，新条目一律撞预算闸门被拒 ——
> 实测表现为**「0 条内嵌、全部走封面兜底」**，而日志只说「累计将超总额度」，看不出是自撞。
> 现已修。

- 脚本：`scripts/media_embed.py`（`download → probe → transcode → size` 一体）
- 产物：`work/videos.json`，key = **全量素材 ID**，值含 `kind / data_uri / size / orig / dur / w / h`
- 实测 14 条全部内嵌，base64 合计约 **9.7MB**，报告 9.8MB
- **`videos.py`（旧：Range 探体积分档）保留但已不是主路径** —— 它的 `≤2MB` 判据会把头部素材全砍掉

**播放行为**（写进卡片的 JS）：

- `IntersectionObserver`：进视口才播（`rootMargin: 140px`、`threshold: 0.25`），滚出即停
  → 14 条视频同时 autoplay 会把页面卡死
- `.mplay` 按钮手动播放 / 暂停（读者要能停）
- `<video muted loop playsinline preload="metadata">` —— **`muted` 是 autoplay 的前提**，
  `playsinline` 少了 iOS 会全屏劫持

### 关键帧

抽帧时间点：**0.6 / 2.6 / 5.4 / 8.6 秒**（对应 0–3s Hook / 3–8s 玩法 / 收口）。
脚本：`scripts/frames.py`（依赖 ffmpeg）。

## 资讯采集

`scripts/news.py` —— 首选 Google News 聚合（采集窗口近 7 天）；**取不到时自动降级到
白名单媒体的直连 RSS**（窗口放宽到 30 天，见下）。

**报告必须含外部媒体文章 ≥3 条**（铁律 11）。纯平台数据回答不了「这游戏最近发生了什么」，
外部资讯是唯一的归因线索。

### ⚠️ Google News 不可达时的直连兜底（无代理的机器必读）

**实测（2026-09-17，本机）**：`news.google.com` 连接超时（`WinError 10060`），
Clash 代理 7897 未开；而国内行业媒体直连正常（百度 200）。
没有这层兜底，「≥3 条」这条硬闸门在无代理机器上**必然过不了**，`validate.py` 会在交付前判 error。

`_fetch_direct()` 走 `FEEDS` 里 5 家实测可达的站点（游戏陀螺／白鲸出海／游戏茶馆／
游戏研究社／触乐，均在本技能的 53 家白名单内）。两个必须知道的差别：

| 项 | Google News | 直连 RSS 兜底 |
|---|---|---|
| 形态 | **搜索 feed**（给词就回相关条目） | **主题 feed**（站点最新文章流，必须客户端按词过滤） |
| 窗口 | 7 天 | **30 天**（`--direct-days`）—— 这些是低频站点，游戏陀螺一个月才 3 条相关的，套 7 天窗口实测只有 1 条 |
| 过滤词 | 产品名/厂商名都行 | **只有品类/赛道词有用**（出海/买量/小游戏/IAA/变现…；`DEFAULT_TOPICS` 已按实测挑好）。产品名一条也捞不到 |
| 链接 | 聚合跳转页，离线读不出去 | **媒体原文地址**，比 Google News 更好 |

**命中的多是行业/品类层面报道，不是该产品直接报道** —— 按「搜不到时的降级」，
必须在 `.cardnote` 里显式写明「暂无该产品直接报道，以下为品类/赛道层面」。

> 另一个常被忽略的点：这些 feed 的最新时间可能**远早于今天**（实测白鲸出海停更在
> 一个月前）。`list` 里看到的日期跨度大是正常的，不是抓错了。

### 信源白名单（53 家，优选）

`news.py` 的 `WHITELIST` 收了 53 家行业媒体，命中即打 `tier="优选"`，`list` 里显示 `[优选]`，
排序上整段置前。分四类：

| 类别 | 家数 | 代表 |
|---|---|---|
| 游戏行业媒体 | 28 | GameLook / 游戏葡萄 / 游戏陀螺 / 游戏茶馆 / 游戏日报 / 竞核 / 触乐 / GameRes 游资网 |
| 出海与全球化 | 10 | 白鲸出海 / 扬帆出海 / 独立出海联合体 / Meetgames 游戏出海 / Android GO 出海 / 点点出海 |
| 营销与商业媒体 | 10 | Morketing / TopMarketing / 36 氪游戏 / 极客公园 / 娱乐资本论 / 互联网怪盗团 |
| 短剧 + 协会官方 | 5 | 短剧自习室 / 中国音数协游戏工委 / 广东省游戏产业协会 / ChinaJoy / 微信公开课 |

**白名单里为什么没有数据平台**：原始名单 62 家，剔除 9 家第三方数据平台
（SensorTower / QuestMobile / 七麦研究院 / DataEye 游戏观察 / DataEye 短剧观察 /
广大大出海笔记 / 广大大短剧笔记 / AI 产品榜 / AI 新榜）后剩 53 家。
剔除理由是**铁律 1**：禁引 Sensor Tower / AppMagic / data.ai 等竞品平台 ——
白名单不该与铁律自相矛盾。这 9 家的报道不是不能看，是**不能署进这份报告**。

- 白名单是**优选**不是排他：表外正规行业/财经/官方媒体仍可入选（Fox News / IGN /
  gamedeveloper 等），但要人工判断信源质量；自媒体与营销号慎用（可能就是产品方自己的投放稿）
- **一条优选源都没有**时 `fetch` 会打 `[WARN]` —— 这时必须在 `.cardnote` 里说明信源筛选取向
- 匹配按信源名双向包含（`GameLook` ↔ `GameLook 快讯`），改名单只需改 `WHITELIST` 一处

### 采集与挑选

- 主题词组合：`{产品名}` / `{开发商}` / `{品类}买量` / `手游营销`
- 数量：**下限 3 条**（低于即 `[BLOCK]`，`validate.py` 交付前再拦一次）；上限 15–20 条，
  筛选标准是**「是否直接改变投放约束或竞争格局」**
- 影响等级：`lv-h` 高（直接改变投放约束）/ `lv-m` 中 / `lv-l` 低
- **中文源（用产品中文名搜）信源质量参差** —— 游戏类**优先保留英文行业源**
  （Fox News / Forbes / IGN / VICE / 官方 / gamedeveloper 等）；
  命中 `BLACKLIST` 的信源由 `news.py` 直接剔除，并在报告里说明筛选取向
- Google News 是**前端跳转**，离线 HTML **无法预解析最终地址** → 按钮只能指向上游聚合入口，
  **必须在 `.cardnote` 里向读者说明**

### 搜不到时的降级（必须显式标注）

先放宽检索词（厂商名 / 品类买量 / 手游营销）。仍然没有该产品的直接报道时，
**可以**放宽到厂商层面 / 同赛道品类层面，但：**数量仍须 ≥3**，且必须在 `.cardnote` 里
显式写明「暂无该产品直接报道，以下为厂商/赛道层面」。

拿泛行业文章冒充该产品报道，比留空更伤信任 —— 客户点开发现说的不是自己产品，
会连带怀疑整份报告的数据。

### 资讯数字与数字保真的边界

资讯表里是**他人文章标题的原文**，天生带日期、排名、金额（实测一行
`09-09 … 《部落冲突》8月流水突破 5000 万美元，全球下载量 TOP3` 会抽出
`['09','09','8','5000','3']`）。这些数字不是本报告的主张，`fidelity.py` 对它们**豁免**。

- 豁免判据是**显式标记**：行内含 `<a class="newsbtn">` → 整行/整项剔除；`#sec-news` 整章剔除
- 所以资讯条目**必须**用 `newsbtn` 承载链接，否则豁免不生效（`validate.py` 的计数也会一起失效）
- 豁免只覆盖资讯引用；**正文陈述里的数字仍要能追到接口字段或登记进 `derived.json`**
- **媒体数字不得搬进正文当论据** —— 资讯是语境，不是数据源。要引用就原句照引并标明出处

## 目录约定

每个报告一个工作区：

```
reports/{product}_{YYYYMMDD}/
    raw/          # aggclaw 原始返回，全部落盘
        data/     # ★ result_L{n}_{tag}.md（分析原文，语料基线）+ 同名 .json（仅元数据）
        materials_all.json / news_all.json
    covers/       # 封面（视频首帧抽出来的，压缩后）
    frames/       # 抽出的关键帧
    work/         # 中间产物（covers.json / videos.json / news.json / derived.json）
    reports/      # 最终 HTML / PDF
```

**分析原文与元数据必须分开落盘**（`claw.py` 已按此实现）：

| 文件 | 内容 | 为什么要分开 |
|---|---|---|
| `result_L{n}_{tag}.md` | `output` 原文逐字 | 保真校验对 `.md` 走纯文本抽取，数字直接可读 |
| `result_L{n}_{tag}.json` | `session_id` / `ok` / `error` / `chars` 等 | `.json` 走 `_walk_scalars` + `_is_encoded()`，**长文本会被整段当编码串丢弃** |

> 早期把整篇 `output` 塞在 JSON 里 → 语料大面积缺失 → 只能靠人工把 output 拆成
> `.md` 放进 `raw/` 补救。现在由 `claw.py` 直接落盘，不要再手工拆，也不要退回单文件方案。

**所有脚本统一从 `--dir <工作区>` 取路径。**
