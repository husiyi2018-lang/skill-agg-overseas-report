# 报告质感:结构铁律 · 口径区块 · 证据链 · 内容质检

> 从 `agg-ad-strategy/references/report-craft.md` 移植，**块映射已改成本技能的积木**（对应 `BLOCKS.md` 编号）。
> 受众为什么不信一份报告？不是数据少，是**不知道数是怎么来的、点不回原始素材、分不清哪句是事实哪句是猜的**。

---

## 0、结构铁律：总分总 + ≤7 + 迭代脑图收尾（违反返工）

人的短期记忆只有 7±2 —— **超过 7 就要分级**。

- **总（开头）= 结论先行**：`hero` 统计 + `sumgrid` 结论摘要（`pos`/`neg` 两栏 ≤6 条）
- **分（中）= 论证主体**：一级导航 **≤7 章**。章节多就合并，宁可章少一点、节拆细
- **总（结尾）= 收口 + 迭代脑图**：先 `aud` 三受众动作 → 再 `flow` 线性承接图（阶段一→二→三）
  → 最后 `mmk` Markmap 交互脑图。**`mmk` 是最后一个内容块**（可缩放/折叠，见 `BLOCKS.md` §25）
- **任何清单 ≤7 项**：方向 / 排行 / 钩子 / 人群 / 建议，单屏一律 ≤7；超出就提炼父项或用表格多列

> ⚠️ 「迭代脑图」= `flow`（线性承接）+ `mmk`（可交互层级）**两件**，不是单一个 `mmtree`。
> `mmtree`（`BLOCKS.md` §10）是更早的纯静态层级树，仍可用，但**不再单独充当收尾脑图**。

> `validate.py` 会自动检查一级导航数与裸表裸图。

## 0b、口径区块：分两层，别混在一起

### 首屏口径条（必须）

放 `hero` 之后、正文之前（shell 的 `{{SCOPE_BAR}}` 槽，用 `<blockquote>`）。
**只写「读者不知道就会读错数」的那几条**，3–6 条、一条一行、不展开推导：

- 数据源与窗口（哪个库 / 哪段日期）
- 样本量与抽样方式（全量 / Top N / 抽样 N 条）
- **最容易被误读的那条口径**（如「素材量≠支出」「占比≠收入」「单条不作共性」）
- 未覆盖维度（aggclaw 明说查不到的，原样保留守卫标记）
- 量级口径说明（如「素材数按窗口内去重计，不含历史存量」）

### 附录完整口径（必须）

方法论 / 多路读数 / 口径冲突 / 样本量 / 来源路 / 抽帧与直链说明全部放这里，
用末章的 `cardnote` 或 `blockquote` + `tablewrap`（数据边界表）。

> 一句话：**首屏放「不知道就会读错」的，附录放「想复现就会用到」的。** 两者不重复。

### 数据口径陷阱（原 pitfalls #14–#18，写作时必读）

> 从 `pitfalls.md` §四整节移来。它是「写正文时必须遵守」的口径规则，
> 而 pitfalls 的定位是「遇到怪问题时查」——放那儿没人读得到。编号保留不重排。

**#14 不同采样口径差异 >20% 时严禁取平均**

aggclaw 两种口径（如「≤31天新增 97,443」vs「首次出现 69,781」）差异可能很大。
→ **正文用主口径，在「数据口径说明」里注明分歧。**

**#15 「素材数」与「广告数」是两个量纲**

不可互推。广告÷素材比在不同品类差异极大（游戏约 18，短剧可达 43）。
**表格里必须分列**，并在口径里解释比值含义。

**#16 「首次投放时间」是监测起点，不是上线时间**

接口返回的是**监测起始日**，产品可能早很多年就上线了。
→ 正文要写清「2021-02-19（监测起点），实际上线 2012」这样的双写。

**#17 创意方向 / Hook / CTA 占比是手工编码**

n=200 样本，**误差约 ±10pp**，属方向性结论。
→ **表格里必须标注 n 与误差范围**，不可当作审计级数据引用。

**#18 数据源表述**

一律写 **[AppGrowing全球广告 AI 策略分析平台](https://appgrowing.ai)**（`shell.html`
的 `side-foot` 已内置这句署名与链接，别删）。
**禁写**有米有数 / youclaw；**禁引** Sensor Tower / AppMagic / data.ai 等竞品平台。
> `validate.py` 的 `check_source_badge` 会机械校验署名与链接，缺任一即 error。

## 0c、证据链三件套：每条结论必须能点回去

报告里任何对「某素材 / 某方向 / 某产品」的判断，挂三件套：

| 要素 | 要求 | 反例 |
|---|---|---|
| **对象** | 素材 ID 用 7 位短 ID，**不截断到看不出** | 「某爆款素材用了悬念钩子」——哪条？ |
| **链接** | 可点的素材详情页 `appgrowing-global.youcloud.com/material/{id}` | 只有 ID、点不开 |
| **来源** | 哪一路 / 哪个字段返回的（**多路时必标**） | 多路结论混写、不标来源 |

- 素材 ID 只能来自 `materials` 清单，**不得推断 / 截断 / 跨对象挪用**
- 多路交叉时标「来自 R2 / R4」或「≥2 路同结论」，让读者能自查
- **指不到字段的结论，一律降级标「推测」，不许写成事实**

对应积木：`fam/mgrid` 卡片的 `.b-lang` 徽标（短 ID）+ 详情页链接；`gal` 卡片的 `gal-verdict` + `g-row`。

## 0d、四层标注：写法固定为 `证据类型 · 置信度`

| 证据类型 | 什么时候用 | 写法示例 |
|---|---|---|
| **数据事实** | 接口字段直接支持 | `数据事实 · 高` |
| **素材共性** | 样本统计支持 | `素材共性 · 中（26 条样本中 21 条）` |
| **策略推断** | 由上面推演，非事实 | `策略推断 · 中` |
| **待验证** | 合理但证据不足 | `待验证 · 低` |

- 置信度**必须带一句为什么**（样本量 / 来源路数 / 是否冲突），裸写「高」不算
- 推断类**必须**出现「推测」或「待验证」字样，不许混进事实里
- 多路结论冲突时，**保留两方口径、不取平均**，标「口径冲突」

对应积木：`<span class="lv lv-h">高</span>` / `lv-m` / `lv-l` 三档徽标，或表格里独立一列。

## 0e、别停在现象：给「不动会怎样 / 立刻做什么」

现象描述不构成决策。对头部洞察写成左右配对：

```html
<blockquote class="warn"><strong>不动会怎样</strong>：{{代价}}</blockquote>
<blockquote class="fix"><strong>立刻做什么</strong>：{{动作}}</blockquote>
```

严格 1:1，**≤3 组**。放 `aud` 三受众之前，与末尾的 `flow` 承接图 + `mmk` 脑图衔接。

## 一、先定叙事骨架，再填数据（顺序不可反）

### 1. 时间轴三段论

不要平铺「近 30 天每天多少条」。按投放节奏切成 3 段，段名直接讲出它的任务：

| 段 | 命名 | 典型任务 |
|---|---|---|
| S1 | 承接铺量 | 上线/预热，试探素材池，承接既有用户 |
| S2 | 集中放量 | 主素材集中投放，量级顶到窗口峰值 |
| S3 | 收敛储备 | 收缩低效方向，沉淀长跑素材，为下一波储备 |

每段给：时间范围、素材量/新增 vs 存量、主投方向、阶段任务一句话。
**段与段之间要有转折逻辑**：为什么从 S1 走到 S2（哪条素材验证有效）→ 为什么 S3 收敛。

对应积木：`stepper`（生命周期步骤条）或 `tl`（时间线）。

### 2. 六方向占比 + 三阶段节奏作骨架

给受众一张「总览骨架」，后续所有证据都挂到这张骨架上：

- **6 个创意方向**作纵轴 × **3 个阶段**作横轴 → 每个方向的每阶段素材占比填进去
- 一眼看出「哪个方向在哪个阶段起量、哪个方向始终陪跑」
- 骨架可以是 `tablewrap`、`chartgrid` 的分组柱状，或 `flow` 线性承接图

这是报告的地图。受众先看它，再决定听哪块细讲。

### 3. 具体证据与动作，填在骨架之下

真正的洞察是「**为什么会这样 + 我方怎么办**」。每条证据写成「变化 + 归因 + 动作」：

- **变化**：旁白覆盖率 +3.6pp、中文原声停更、媒体分工从单一到拆散…
- **归因**：对应哪个阶段、哪个方向的策略意图（数据能指到才写，指不到标推测）
- **动作**：落到「素材团队下批做什么」

> 反例：单列「ASR 覆盖率 62%」——受众不知道要拿它干嘛。
> 正例：「S2 起旁白覆盖率 +3.6pp，集中在福利引导类；但纯声类无人做，是下批可试的空位。」

### 4. 题材赛道级归类（不只列产品）

涉及多产品/多地区时，按**题材赛道**归类（而非流水账列举），再讲赛道间差异。

## 二、内容质检（每条结论都要过）

### 1. 从现象到原理（战略层，不只战术层）

对头部洞察，不只说「发生了什么」，再往下拆一层「为什么会这样（机制/算法/人群）」。
例如某方向衰减：战术层是「量掉了」，战略层是「同质化导致 eCPM 抬升、系统减少探索分配」。
**数据指不到的机制要标「推测」，不许编。**

### 2. 站得住的 3-4 条，做成三列收口

全文收敛后，挑 3–4 条最有把握、最该行动的洞察：

```html
<div class="tablewrap"><table>
  <thead><tr><th>核心洞察</th><th>证据类型 · 置信度</th><th>一句话动作</th></tr></thead>
  <tbody>
    <tr><td>{{洞察}}</td><td>数据事实 · 高</td><td>{{动作}}</td></tr>
  </tbody>
</table></div>
```

这 3–4 条 = 受众「带走」的部分；其余分析是支撑它的论证过程。

## 三、质检红线（违反即返工）

- [ ] 有一条时间主线（S1→S2→S3），不是并列堆维度
- [ ] 方向 × 阶段的骨架在，具体证据挂在骨架之下
- [ ] 每条重要结论有「证据类型 · 置信度」，推断类显式标「推测/待验证」
- [ ] 头部洞察有战略层解释（现象→机制），**未编造算法原理**
- [ ] 结尾有 3–4 条「证据 · 置信度 · 动作」三列收口
- [ ] 末尾是**迭代脑图**：`flow` 线性承接图 + `mmk` Markmap 交互脑图（`mmk` 最后）
- [ ] 首屏有口径条，附录有完整方法论
- [ ] **数据口径陷阱逐条过**（§0b）：多路差异 >20% 未取平均且已注明分歧；素材数与广告数分列未互推；首次投放时间写成「监测起点」而非上线时间；手工编码占比标了 n 与 ±10pp；数据源署名统一
- [ ] **数字全部通过 `validate.py --dir <工作区>` 的保真校验**（未命中的已进 `work/derived.json`）
- [ ] 素材卡封面真实、ID 可溯源（7 位 hex、全站不重复）；封面兜底的已在口径注明
- [ ] 视觉：零 CDN 外链、打印样式可用、脑图不溢出
